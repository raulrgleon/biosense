Por qué existe

La electrónica necesita un banco reproducible antes de tener curvas de electrodo.

Cambiar RF, el filtro o la resolución del ADC no debería hacerse a ciegas. Tampoco debería hacerse sobre un paciente, ni fingiendo que un modelo lineal ya es un sensor caracterizado.

BioSense ocupa ese hueco: un banco de ingeniería donde la cadena sensor → TIA → filtro → ADC → algoritmo se puede recorrer, estresar y exportar. Los huecos marcados PROVISIONAL están a la vista. El objetivo es sustituirlos por datos de laboratorio, no esconderlos.

Es un proyecto de DNET. La ficha del estudio está en dnet.llc/proyectos/biosense.

Qué simula

Tres canales. Ninguno comparte estado con el otro.

CH1

Glucosa

Sensor electroquímico, TIA, filtro y ADC. La sensibilidad por defecto es 1 nA por mg/dL: un parámetro provisional, no una curva de electrodo.

CH2

Oxígeno

Segundo canal electroquímico, con su propio TIA y filtro. La unidad es sim, no mmHg ni saturación. La influencia sobre glucosa está apagada.

CH3

Temperatura

Hoy entra por control, en °C. El ADC CH3 queda reservado para un sensor físico. El coeficiente térmico está en 0 %/°C.

Cómo recorre la señal

La misma cadena, tres veces.

  1. 01

    Sensor

    Corriente modelo: glucosa · sensibilidad + baseline + deriva + ruido. El ruido es gaussiano de media cero.

  2. 02

    TIA

    VOUT = VREF + I · RF. Satura contra 0 V y 3.3 V. A partir de ahí la cadena usa la tensión recortada.

  3. 03

    Filtro

    Paso bajo de primer orden. Con RF = 1 MΩ y CF = 100 nF, fc ≈ 1.59 Hz. En marcha el paso es 0.1 s.

  4. 04

    ADC

    CH1 glucosa, CH2 oxígeno, CH3 temperatura. 12 bit por defecto. El error de cuantificación no se esconde.

  5. 05

    Algoritmo

    Reconstruye corriente, resta baseline y deriva, y estima glucosa. El ruido no se resta: el estimador no conoce la muestra aleatoria.

Caso de referencia

200 mg/dL no se “ajusta” a 200. Se cuantifica.

Glucosa 200 mg/dL, sensibilidad 1, 37 °C, ruido 0, deriva 0, VREF 1.65 V, RF 1 MΩ, ADC 12 bit. La diferencia de ≈ 0.26 mg/dL es el escalón del convertidor, no un truco de calibración.

Cómo se usa

Un motor. Tres puertas.

Interfaz

Sesión, gráficas, escenarios, barrido de calibración y exportación a PDF, CSV y JSON. El motor de la UI es el mismo que el de la API.

Documentación API

MCP

Servidor remoto Streamable HTTP. Entra con API key o con OAuth 2.1 (Auth0, PKCE). Pensado para un agente, no para un paciente.

Lo que no es

No es un glucómetro. No es un ensayo clínico. No es un electrodo medido.

  • 1 mg/dL = 1 nA es una convención de banco, no la curva de un sensor físico.
  • Oxígeno usa unidades sim. No es presión parcial ni saturación.
  • La temperatura del algoritmo es el valor del control, no una termistor caracterizada.
  • Los escenarios (comida, rampa, escalón) son señales de prueba. Ninguno es un registro fisiológico.
  • GOOD / WARNING / INVALID habla de saturación y ruido de simulación, no de criterio médico.

Preguntas cortas

Para no dar vueltas.

¿Puedo usarlo para decidir un tratamiento?

No. Es un instrumento de desarrollo. No mide sangre, intersticio ni ningún tejido.

¿De dónde salen los números?

De un modelo lineal explícito, con ruido gaussiano y electrónica de banco configurable. Todo lo que falta una curva de laboratorio está marcado PROVISIONAL en el motor.

¿El sitio y el simulador son la misma app?

No. biosense.dev es esta página. El motor vive en app.biosense.dev, a partir del repositorio biosense-simulator. No comparte secretos con el sitio.

¿Cómo lo abre un agente?

Por MCP en https://app.biosense.dev/mcp, con clave de API o OAuth 2.1. Los alcances son biosense:read y biosense:simulate.
